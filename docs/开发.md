# 开发

## 从源码运行

```powershell
py -3.12 -m venv .build\venv
.build\venv\Scripts\python.exe -m pip install -r requirements.txt
.build\venv\Scripts\python.exe launcher_server.py
```

依赖清单见 [requirements.txt](../requirements.txt)，版本已钉住。也可以双击 `start_web.vbs` 启动。

**注意**：`icons/` 目录未包含在本仓库中（原因见 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md)）。
缺少它不影响运行，只是应用列表中的图标会走降级显示。如需完整图标效果，
跑一次 `scripts\fetch_icons.py` 自动补齐（见下方[图标素材库](#图标素材库)），
或自行准备以包名命名的 `.webp` 文件放入 `icons/`。`scrcpy/` 目录已包含，无需另外下载。

## 项目结构

```
launcher_server.py        入口薄壳：单实例互斥、起 HTTP 服务、建窗口、接托盘与退出收尾
kuaitou/                  后端实现（按职责分模块）
  storage.py                路径常量 + ADS 存储 / 配置 / 日志
  device.py                 adb / scrcpy 封装、设备状态、投屏、子进程管理
  discover.py               三级设备发现（局域网 / mDNS / 端口扫描）
  apps.py                   应用列表扫描 + 图标库匹配
  system.py                 扫码配对、诊断、托盘、开机自启
  web.py                    HTTP 路由与 js_api
index.html                前端界面（原生 JS，无构建）
requirements.txt          运行与打包依赖（含版本钉死）
config.json               默认配置
appicon.ico               应用图标
KuaitouBuild.spec         PyInstaller 打包配置
start_web.vbs             源码态启动脚本
scrcpy/                   随附的 scrcpy / adb 运行时（第三方，见声明）
icons/                    应用图标库（未入库）
android/                  手机侧取图程序的源码与打包脚本（icondump.dex 随包分发）
tests/                    pytest 测试（图标匹配 / 配置合并 / adb 解析等纯逻辑）
scripts/fetch_icons.py    图标素材库维护脚本（补图 + 瘦身）
scripts/check_exe_version.py  校验 exe 内版本号与源码一致（CI 与发版都靠它兜底）
scripts/release.py        一键发版：打包 → 校验 → 打标签 → 建 Release → 传资产
release_notes/            每版发布说明（入库，发版时由脚本读）
pyproject.toml            ruff 与 pytest 配置
```

模块依赖是单向的：`storage ← device ← discover ← web`，`apps` / `system` 建于其上，
入口 `launcher_server.py` 只负责组装。深度搜索的进度通过 SSE（`/api/discover/deep/stream`）
推送，前端在 EventSource 不可用或断线时自动回退到 700ms 轮询。

三级设备发现的做法与端口扫描的并发取舍（在飞连接数为什么压在 640、为什么用
`selectors` 而不是线程池）都写在 `kuaitou/discover.py` 的注释里；图标匹配的多级回退链
写在 `kuaitou/apps.py`。这两块的取舍跟代码贴得比跟文档紧，改动时以那边为准。

## 测试与 CI

```powershell
.build\venv\Scripts\python.exe -m ruff check .     # 静态检查（配置见 pyproject.toml）
.build\venv\Scripts\python.exe -m pytest -q        # 跑测试
```

测试只覆盖纯逻辑（图标匹配、配置合并、路径解析、adb 输出解析），不碰真机也不联网，
所以在任何机器上都秒级跑完。CI（[.github/workflows/ci.yml](../.github/workflows/ci.yml)）
对每个提交跑三个 job：`lint`（ubuntu 上跑 ruff）、`test`（windows-latest 上跑 pytest）、
`package`（windows-latest 上照 `KuaitouBuild.spec` 真打一次包，再用 `scripts/check_exe_version.py`
校验产物里带的版本号与源码 `APP_VERSION` 一致）。

最后那个 job 是给发版兜底的：**忘了升版本号，CI 就会红**，包发不出去。

## 打包

```powershell
.build\venv\Scripts\python.exe -m PyInstaller --noconfirm --clean KuaitouBuild.spec
```

产物在 `dist\快投.exe`。

打包参数只在 `KuaitouBuild.spec` 里维护**一处**，别再从命令行手工拼参数：那样跑完 PyInstaller
会在当前目录另生成一份按 `--name` 自动命名的 spec，同一份配置就变成两份，早晚各改各的漂移。

`icons/` 未入库（图标版权原因），所以从干净克隆打包时它不存在。spec 会把缺失的打包源跳过并在
stderr 打一行警告，**照常能打出包**——少的是内置图标素材库，运行时仍会在线抓图、并从手机取真实
图标，只是界面图标先走降级显示。想让内置素材库进包，打包前先跑 `scripts/fetch_icons.py` 补回来。

版本号在 `kuaitou/storage.py` 的 `APP_VERSION`，按改动大小走，别一路上涨：

| 位 | 什么时候动 | 例子 |
| --- | --- | --- |
| 第一位 | 大更新（大改版、不兼容的变化） | 1.x → 2.0.0 |
| 第二位 | 小更新（加功能、加选项） | 1.8.0 → 1.9.0 |
| 第三位 | 单纯修 bug | 1.8.0 → 1.8.1 |

## 发版

先写发布说明并提交（入库到 `release_notes/<tag>.md`，跟代码一起 review），然后一条命令发出去：

```powershell
.build\venv\Scripts\python.exe scripts\release.py v1.9.0 --dry-run   # 先空跑，看会发出什么
.build\venv\Scripts\python.exe scripts\release.py v1.9.0             # 正式发
```

脚本依次做：核对标签版本号与 `APP_VERSION` 一致 → 检查工作区干净 → 打包 → 校验产物 →
打标签并推送 → 建 GitHub Release → 把 `dist\快投.exe` 以 `Kuaitou-<tag>.exe` 的名字传上去
（GitHub 不支持中文资产名，会被清成 `default.exe`）。哪一步不对就停在哪一步并说明原因，
不会带病往下走。

其他开关：`--no-build` 用已有产物发、`--draft` 建草稿、`--prerelease` 标预发布、`--force`
覆盖同名资产、`--update-repo-meta` 顺带更新仓库描述与 topics。凭据优先读环境变量
`GITHUB_TOKEN`，没有就用本机已存的 git 凭据。

## 图标素材库

`icons/` 不入库，换台机器重新打包前用脚本补回来：

```powershell
.build\venv\Scripts\python.exe scripts\fetch_icons.py          # 只补缺的
.build\venv\Scripts\python.exe scripts\fetch_icons.py --slim   # 顺带统一到 128px WebP
.build\venv\Scripts\python.exe scripts\fetch_icons.py --limit 20
```

目标包名来自脚本内置的常用应用清单 + 本机 `apps_cache.json` 里真机装过的应用，
图标来源与程序运行时在线抓取用的是同一套（应用宝 → 小米商店 → iTunes）。
`--slim` 会把整个素材库统一成 128px WebP（界面里图标最大显示 48px，够 2 倍屏用），
体积大约降到原来的四成。

## 手机侧取图程序（dex）

`android/icondump.dex` 随包分发，源码在 `android/icondump/`。它只做一件事：把手机里每个
能启动的应用的图标渲染成 PNG，打成一个 zip 放在 `/data/local/tmp/`，电脑再拉回来入库。

跑法是 **dex + `app_process`**，不往手机装 App、不申请任何权限：

```powershell
adb push android/icondump.dex /data/local/tmp/kuaitou_icondump.dex
adb shell CLASSPATH=/data/local/tmp/kuaitou_icondump.dex app_process /system/bin `
  com.kuaitou.icondump.IconDump /data/local/tmp/kuaitou_icons.zip
```

进程以 shell 身份运行（uid 2000），`/data/app` 下的 base.apk 对它可读，所以能直接解出
别的应用的图标资源。全程没有界面，也不会像装 App 那样在手机上留下东西——导出和拉取都完事
后电脑会把推上去的 dex 和 zip 删掉。

这条路踩过的坑（`app_process` 里起不了应用上下文得走 `ServiceManager` 反射、
`getInstalledPackages` 返回的是 `ParceledListSlice` 少调一次 `getList()` 就会抛
`ClassCastException`、自适应图标为什么要补圆角裁剪且不能再放大）都写在
`android/icondump/src/com/kuaitou/icondump/IconDump.java` 的注释里，改动前先读那里。

改了源码后用 `android/build.ps1` 重新打包。它不走 Gradle（这个程序没有资源文件、没有第三方
依赖），直接 javac → d8 两步出产物：

```powershell
powershell -ExecutionPolicy Bypass -File android\build.ps1
```

需要 JDK 17 与 Android SDK 的 build-tools 35.0.1、platform android-35，放成这样即可：

```
.build/toolchain/jdk-17.0.20.1+1
.build/toolchain/sdk/build-tools/35.0.1
.build/toolchain/sdk/platforms/android-35/android.jar
```
